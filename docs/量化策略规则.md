# QQQ 0DTE 量化交易策略规则与架构解析文档

> 📌 **适用对象**：量化开发者 / 期权交易员 / 策略研究员  
> 📌 **核心标的**：`QQQ` 1分钟K线 & 当日到期（0DTE）期权  
> 📌 **架构设计**：`strategy.py`（纯数学/状态逻辑） + `trader.py`（API交互/订单执行/持久化），实现实盘与回测 **100% 代码共用**。

---

## 🧠 一、 策略核心设计理念
0DTE 期权具有 **Theta 衰减极快、Gamma 爆发集中、流动性日内分化** 的特征。本策略摒弃主观预测，采用 **规则驱动的状态机**：
1. **过滤噪音**：仅在高波动窗口（开盘后30min~收盘前10min）交易，避开盘前盘后流动性枯竭期。
2. **双信号引擎**：趋势突破（动量跟随） + 均值反转（超跌/超买修复），互为补充。
3. **刚性风控**：高水位线移动止损 + 时间止损 + 日亏损熔断，杜绝“扛单”与“情绪交易”。
4. **执行解耦**：策略层不触碰网络/文件系统，保障回测可复现性；执行层负责订单路由与状态持久化。

## 🔄 二、 交易流程节点逐一展开

### 2.1 🕒 交易窗口与时间过滤
**规则**：仅在美东时间 `09:30 ~ 16:00` 交易，严格过滤周末及盘前/盘后数据。  
**代码实现**：`strategy.is_trading_hours()`
```python
def is_trading_hours(self, raw_ts: Optional[datetime] = None) -> bool:
    if raw_ts is None:
        bar_ts = datetime.now(CONFIG["tz_et"])
    # ... (类型安全解析 int/str/datetime)
    if bar_ts.weekday() >= 5: return False
    market_open = bar_ts.replace(hour=9, minute=30, second=0, microsecond=0)
    market_close = bar_ts.replace(hour=16, minute=0, second=0, microsecond=0)
    return market_open <= bar_ts <= market_close
```
💡 **设计意图**：0DTE 期权在 `14:00 ET` 后 Theta 呈指数级衰减，窗口过滤避免无意义持仓磨损。

### 2.2 📡 信号生成引擎（双轨制）
策略在每根确认的 1分钟K线到达时，调用 `generate_signal()` 依次评估：

#### 🔹 A. 趋势突破信号 (`_breakout_signal`)
**触发条件（四重确认）**：
1. `SMA20` 过滤：价格 > SMA20（仅做多） / 价格 < SMA20（仅做空）
2. `突破`：当前K线收盘价 > 前5根最高价（Call） / < 前5根最低价（Put）
3. `量能`：当前成交量 ≥ 动态/标准阈值（见 2.2-C）
4. `K线实体`：`abs(close-open)/close ≥ 0.03%`，过滤十字星/长影线假突破

#### 🔹 B. 均值反转信号 (`_reversal_signal`)
**触发条件**：
1. 参考过去20根K线的高低点范围
2. **看跌反转**：从20根内最高点回落 ≥ `0.2%`，且当前收阴线
3. **看涨反转**：从20根内最低点反弹 ≥ `0.2%`，且当前收阳线
4. 同样需满足 `min_body_pct` 实体过滤

#### 🔹 C. 量能动态门槛 (`_volume_ok`)
```python
cnt = len(self.sma20_vol)
if cnt < 20:
    # 开盘初期数据不足，动态提高门槛（上限1.5倍），防早盘虚假放量
    dynamic_mult = min(CONFIG["vol_mult"] * (20 / cnt), 1.5)
    return self.bars[-1]["volume"] >= (sum(self.sma20_vol)/cnt) * dynamic_mult
# 满20根后使用标准阈值
return self.bars[-1]["volume"] >= (sum(self.sma20_vol)/20) * CONFIG["vol_mult"]
```

### 2.3 📥 订单执行与开仓 (`trader.py`)
**流程**：生成合约代码 → 提交市价单 → 轮询成交 → 确认成交价 → 更新策略状态
```python
def _execute_open(self, side: str, stock_price: float):
    symbol = QQQStrategy.generate_option_symbol(stock_price, side) # QQQ260509C452000.US
    order = Order(symbol=symbol, quantity=CONFIG["max_position_size"],
                  side=OrderSide.Buy, order_type=OrderType.MO, time_in_force=TimeInForceType.Day)
    order_id = self.tc.submit_order(order)
    fill_price = self._wait_for_order_fill(order_id) # 轮询历史订单状态
    self.strategy.open_position(side, stock_price, fill_price, symbol) # 记录 entry_opt
```
⚠️ **注意**：0DTE 期权点差较大，实盘建议后续升级为 `限价单+动态滑点容忍` 或 `IOC` 订单。

### 2.4 📊 持仓管理与动态退出 (`check_position_exit`)
采用 **高水位线（High-Water Mark）+ 时间止损** 的混合退出机制，按优先级依次判断：

| 退出类型 | 触发条件 | 代码逻辑 | 量化意义 |
|:---|:---|:---|:---|
| **STOP_LOSS** | 浮亏 ≥ 25% | `pnl_pct <= -CONFIG["sl_pct"]` | 截断亏损，防期权归零风险 |
| **TAKE_PROFIT** | 历史最高浮盈 ≥ 100% | `peak >= CONFIG["tp_half"]` | 利润落袋，避免“过山车” |
| **TRAILING_STOP** | 回撤 ≥ 30%（从峰值算） | `peak > 0 and (peak - pnl_pct) >= 0.30` | 让利润奔跑，动态保护浮盈 |
| **TIMEOUT** | 持仓 ≥ 15根K线（15分钟） | `bars_held >= CONFIG["timeout_bars"]` | 对抗 Theta 衰减，释放资金效率 |

**核心代码**：
```python
peak = max(self.position.get("peak_pnl", 0), pnl_pct)
self.position["peak_pnl"] = peak # 持久化高水位线
if pnl_pct <= -0.25: return "STOP_LOSS"
if peak >= 1.0: return "TAKE_PROFIT"
if peak > 0 and (peak - pnl_pct) >= 0.30: return "TRAILING_STOP"
self.position["bars_held"] += 1
if self.position["bars_held"] >= 15: return "TIMEOUT"
```

### 2.5 🛑 日终风控与状态重置
- **熔断机制**：`daily_pnl ≤ max_daily_loss` 或 `consecutive_losses ≥ 3` → 触发 `emergency_stopped = True`，当日停止所有新开仓。
- **每日重置**：适配器检测到日期切换时调用 `reset_daily()`，清空盈亏、连亏计数、熔断状态，确保次日从零开始。

## 🛠️ 三、 现有策略改进建议（量化级优化）

### 1. ⏱️ 超时阈值应动态化（强烈建议）
当前 `timeout_bars=15` 为固定值。0DTE 不同时段波动特征差异极大：
- `09:35~11:30`：趋势延续性强 → 可保留 15~20 bars
- `11:30~13:30`：午盘震荡，Theta 加速 → 应缩短至 8~10 bars
- `13:30~15:30`：尾盘 Gamma 爆发 → 应严格控制在 5 bars 内
**改造方案**：在 `check_position_exit` 中根据 `bar["ts"].hour` 动态读取 `CONFIG` 中的时段阈值，或传入 `timeout_bars` 参数。

### 2. 📉 信号冲突与冷却机制缺失
突破与反转信号可能在同一根K线或相邻K线连续触发，导致频繁开平仓。
**改进**：引入 `signal_cooldown`（如信号触发后至少间隔 3 根K线才可再次开仓），或在 `generate_signal()` 中设置优先级（如：突破优先于反转）。

### 3. 💰 仓位管理过于静态
当前 `quantity=CONFIG["max_position_size"]` 为固定手数。专业做法应结合 **波动率调整** 或 **凯利公式**：
```python
# 示例：根据 ATR 或隐含波动率 IV 动态调整手数
dynamic_size = int(CONFIG["base_size"] * (TARGET_VOL / CURRENT_ATR))
```

### 4. 📡 执行层滑点控制
市价单 (`OrderType.MO`) 在 0DTE 期权盘中极易遭遇宽点差与滑点。
**改进**：
- 改用 `Limit Order`，价格 = `最新成交价 ± 滑点容忍度`
- 设置 `TimeInForceType.IOC`（Immediate-or-Cancel），未立即成交则撤单重试，避免挂在盘口被反向吞噬。

### 5. 🔄 回测确定性加固
`is_trading_hours` 中 `if raw_ts is None: bar_ts = datetime.now(...)` 会破坏回测可复现性。
**改进**：在策略层强制要求传入 `raw_ts`，回测引擎必须注入时间戳。可改为：
```python
if raw_ts is None:
    raise ValueError("回测环境必须传入 raw_ts，禁止依赖系统时间")
```

### 6. 📦 异常恢复与原子写入
`_save_state()` 直接覆盖 JSON，若进程崩溃可能导致文件截断。
**改进**：使用 `tempfile` + `os.replace()` 实现原子写入，或引入 SQLite 替代 JSON 存储状态。
